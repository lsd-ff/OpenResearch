# 普通代码自动恢复

本批补齐 Go `CoderAgent` 的普通代码语法/API 修复、缺失模块补装及重新执行路径。科研/框架计划初始准备、依赖删除/替换、执行阶段环境变更与重新预检已另行接通，见 [环境恢复](environment-recovery.md)；自动运行时选择仍待迁移，不能由本批普通代码用例替代验收。

## 使用和边界

在聊天中提供 Python 代码，并要求「直接执行以下代码并修复错误」，系统会自动创建并排队执行，完成后返回实际输出和修复次数。只规划、不要执行及审批设置继续生效；显式 `/api/plan` 仍可创建计划后按原接口运行。

新计划包含代码准备和程序执行两个阶段，各自最多 2 次修复、3 次检查/运行尝试。`OPENRESEARCH_CODE_MAX_REPAIRS` 取值为 0–2，设为 0 关闭自动修复。用户明确的「不要修改代码」「不要安装依赖」「不要自动修复」会收紧服务器任务权限，模型不能绕过；代码不可变时仍可按授权补装依赖。它不替代节点超时、计划预算、取消、租约或权限检查。

- 准备阶段按目标 Python 3.12 语法检查，必要时让真实模型提出语法修复；未执行程序，不能把检查次数写成实验运行次数。
- 执行阶段实际运行后，针对 `ImportError/ModuleNotFoundError/AttributeError/NameError/TypeError/SyntaxError` 等受支持错误提出修复。每次重跑使用新容器。
- 常见缺失模块有明确的包映射，例如 `yaml → PyYAML`；其他提议仍须解析公开包、固定完整 wheel 闭包、验证平台/版本/SHA，并确认 wheel 确实包含缺失模块。容器只做离线安装，不拿到模型凭据、代理或下载权限。
- 修复以用户原始目标为准，规划器重写的节点描述不能替代它；模型可读取当前冻结依赖版本。用户明确的版本约束参与依赖解析的交集，模型不能通过放宽提议覆盖用户固定版本。
- 代码变更必须保留既有断言、显式 raise、测试函数、测试调用、控制分支以及已经使用的库；不能把真实库换成字面量、把断言放进不可达分支或捕获后假装成功。语法阶段不能顺带改写原有运算和字面量，无法安全核对的修复会拒绝。
- 真实 `AssertionError` 保持失败，不让模型删除或弱化测试。哈希、输出文件、权限及不支持的环境错误不能借普通代码修复绕过。标准库故障不能被模型改为从 PyPI 安装同名替身。
- 没有模型、模型提议无效、依赖不可用或预算用尽时保持失败并保存诊断，不产生模拟成功。

旧计划缺少新权限与产物契约时继续走原执行路径，不能因为升级自动扩大权限。

## 可审计产物

新计划保存 `generated_code`、`code_preparation_report`、`run_metrics`、`execution_files`、`executed_code` 和 `code_recovery_report`。准备报告与执行报告分开；每次尝试记录代码及其摘要、实际容器 ID/镜像摘要、安装环境与依赖锁、退出码和失败诊断。实际代码退出 0 但输出收集不合格时仍失败。

报告中每次 stdout/stderr 保留有界片段并标记截断；实际执行日志仍进入持久事件流。最终 `run_metrics` 保存实际进程输出，不把安装失败当成代码已经运行成功。失败可只提交声明过的诊断产物，不伪造缺失或被拒绝的 `execution_files`；成功仍必须交付完整契约。强制超时或取消可能仅保留事件与失败状态，容器仍须回收。

## 2026-10-20 真实验证

使用用户配置的真实模型及原生 Docker，回执位于忽略路径 `.data/parity-live/code-recovery-6372373850a9403988d4da0af2159a06/`。

| 场景 | 计划 | 实际结果 |
| --- | --- | --- |
| JSON API 错误 | `c307d8f8b796482bb782216d60170a86` | 首次真实 AttributeError，模型将 `json.decode` 修为 `json.loads`，新容器重跑退出 0，输出 value=7 与标准库实际路径 |
| 缺失 PyYAML | `bd9fcbcf92bb4c0dae1b9ad035e866f9` | 首次 ModuleNotFoundError，固定/校验 PyYAML 6.0.3 wheel 后离线安装，新容器输出 value=9 与 `/workspace/environment/yaml/__init__.py` |
| 缺少冒号 | `377b7c7c7a684f46bcd8be57b9db8738` | 实际模型修复语法，保留原断言，随后真实容器输出 11 |
| 故意失败的断言 | `dd3f4ffd061f40e39c9fbd0095dbe98a` | 真实 AssertionError，保持 failed，1 次运行、0 次修复；没有伪造通过 |

这些是恢复协议的功能样例，不证明任意程序都能自动修好，也不构成科研效果证据。网页回归中的 API 修复提议由受控模型夹具给出；错误、两个容器、代码实际运行及输出来自真实执行，真实模型验证则来自上表独立回执。

## 工程回归与交付状态

本批默认门禁 409 项通过，Ruff、严格 mypy（179 个源文件）及 wheel/sdist 构建通过。真实 Docker 总回归 28 项通过，4 项按外部下载或独立服务开关跳过；其中 PyYAML 外网固定版本验收另行执行并通过，框架真实库验收沿用上一批独立回执，不把本轮跳过视为重新通过。代码恢复和产物收集边界的 4 项针对性 Docker 回归通过。前端 lint/build 及 12 项网页回归通过，包含两次真实运行后的 API 修复报告与刷新去重。

新增行为测试确认代码块内的「直接执行」「不要自动修复」字符串不会代替代码块外的用户指令。普通代码与科研仓库执行的恢复路径仍有区别；研究环境与运行时恢复未由这批交付补齐。上述结果属于迁移开发分支，尚未合并主分支并完成最终部署验收。
