# 公共 HTTP/HTTPS PDF

开发分支已扩展原先仅 arXiv 的下载入口。聊天中可输入「阅读 https://example.org/paper.pdf」或提供返回 PDF 的公共下载地址，生成绑定真实附件的阅读计划；可直接用消息按钮查看文件，执行计划后再在沙箱提取并分析内容。也可使用 `/api/pdf-proxy?url=...`。有效 arXiv `/abs/` 链接仍转换到对应 PDF。最终统一部署尚待验收，不能以本页证明 Go 全功能迁移完成。

## 网络与数据边界

- 仅 HTTP/HTTPS，URL 上限 4096 字符，拒绝用户信息、非法端口及控制字符。主机名解析得到的全部地址必须为公共地址，回环、内网、链路本地、组播及私网映射地址都会被拒绝。
- 每次连接只使用已校验 IP，保留原始 Host、TLS 域名和证书校验；连接池不保留空闲连接，重定向的每次新连接重新检查 DNS，不能在校验之后再次按原域名拨号。最多 5 次重定向，缺失位置、非 HTTP(S) 或指向私网都会失败。
- `OPENRESEARCH_SOURCE_PROXY_URL` 可显式指定 HTTP/HTTPS 代理，未设置时直连，不自动继承系统代理。代理 CONNECT 同样以已校验的公共 IP 为目标，TLS 仍核对原域名。代理认证仅发往代理；浏览器/API 身份、模型凭据及前一跳 Cookie 不传给下载源。SOCKS 代理不在当前 PDF 契约内。
- 必须是 HTTP 200、`application/pdf` 和 `%PDF-` 签名，登录 HTML 不会被当作论文。默认解码后大小为上传上限 32 MiB；支持 identity/gzip，gzip 流式限制输出并检查完整性，编码体也有界。临时网络/429/502/503/504 最多重试 3 次，DNS、重定向、等待及读取共用来源下载期限，错误不暴露签名参数或代理认证。

网络传输适配使用公开 httpcore 接口，并在项目及锁文件声明 `httpcore>=1.0.9,<1.1`。下载只处理有界字节与元数据，不在宿主解析不可信 PDF；逐页文本提取继续在沙箱中进行。没有新增 OCR、网页登录或私网站点访问。

## 归属与网页阅读

聊天只下载用户明确提供的链接，或用户选中的实际检索来源。原始字节保存为所属用户的上传记录，冻结 SHA-256；计划及后续页码、文本都引用同一附件。`papers` 响应只返回本次计划中的 PDF 公共元数据，其他用户仍得到 404，内部路径不暴露。

聊天按钮按实际文件名打开已经保存的附件，不再指向固定 Transformer 示例，也不为 CSV 生成论文入口。文件名、内容地址与摘要随消息保存在本地会话，刷新后仍可打开同一份字节；旧消息没有实际附件绑定时不会猜测论文地址。
