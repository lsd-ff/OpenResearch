# 小型实验与 Benchmark 协议

## 最小示例

examples/benchmark.csv 为四条协议测试数据，examples/openresearch_run.py 根据输入特征生成预测。它用于验收管线，不是论文数据或效果证据。不要在宿主机直接运行实验入口；通过计划传给沙箱。

在工作台「高级实验设置」上传该 CSV，输入列 x、目标列 y、样本 ID 列 id、任务分类；粘贴示例代码，设置 accuracy 最低值 1，消融参数 --disable-parity，生成并执行。真实结果应为基线 1.0、消融 0.5，阈值标准在执行前冻结。scripts/verify_deployment.py 自动执行相同协议并下载真实报告。

## 直接运行真实仓库的测试

普通对话无需填写高级表单。已有 pytest 套件覆盖用户目标时，自动设计选择真实的 `test_paths`，服务端生成固定启动器，在锁定依赖的沙箱中通过 `pytest.main` 执行完整文件，保留实际通过数、失败回溯和退出码。代码生成模型不需要重新编写这套测试。

`test_paths` 最多包含 8 个固定仓库中存在的相对 `.py` 路径，不允许目录跳转或 `::case` 子集选择；选中的测试文件不能成为补丁路径。启动器不允许被替换或添加筛选条件，文件参数置于 `--` 后。此模式不能替代 Benchmark、消融或自定义命令行参数；需要新实验逻辑的请求仍使用模型适配器和有界自动修复。

## 输入与输出

CSV / TSV 要有唯一非空列名；JSONL 每行是一个对象。显式指定特征列、目标列和可选 ID 列；目标列和 ID 列不能作为特征。没有 ID 列时用零起始行号字符串。默认最多 2000 行，拒绝空集、重复 ID、缺少字段和超预算数据。

容器内 OPENRESEARCH_INPUT 指向 JSON 数组，每项为：

```json
{"id":"a","inputs":{"x":"1"}}
```

入口向 OPENRESEARCH_PREDICTIONS 写入 JSON 数组，每项只包含：

```json
{"id":"a","prediction":"yes"}
```

每个输入恰好一个预测，顺序不限；缺失、重复、未知 ID 和非有限回归数值均失败。实验不能访问目标文件，目标由服务端评估持有。这是列映射隔离，不构成完整防泄漏研究协议；真实数据拆分、预处理与实验设计仍需用户明确声明。

分类支持 accuracy 与 macro_f1，回归支持 mse、mae、r2。服务端根据完整预测重算，不接受实验自报分数。消融复用最终代码和依赖锁，仅改变声明的 argv；报告包含原始分数及基线差值。

新建 Benchmark 计划在正式执行前包含独立 `benchmark_preflight` 节点：从已验证的数据契约中取前 8 条（不足则全取），在独立容器中实际运行适配器并重算指标，目标值不传入容器。预检可进行声明次数内的补丁修复，最终代码、来源数据、研究协议和依赖锁的摘要在正式运行前再次核对。预检失败阻断后继，并保存 `benchmark_preflight_report` 与最后补丁；通过后在新容器运行完整数据集，报告中的 `preflight` 单列预检回执，不把小样本通过当作全量成功。旧版已保存的计划保留原执行方式。

正式运行失败后，任何补丁变更都会使此前预检失效。具有 `benchmark.preflight` 权限的新计划必须在另一个容器重新运行相同的最多 8 条样本，通过后才可重跑全量数据；重新预检失败时只在剩余修复预算内继续修复，不启动全量任务。修复次数与正式运行共用原节点预算，不为预检嵌套创建另一轮修复预算。`research_report.preflight_rechecks` 保存按顺序发生的全部重新预检，原始全量失败与重新预检失败同时进入聊天汇总历史。旧节点缺少重新预检权限时不会被升级扩权，也不能修复后绕过门禁。

## 有界 ToT 消融

自然语言明确请求消融且未指定固定变体时，计划增加 Data Agent 的 `ablation_design` 阶段。也可通过 ResearchSpec 的 `ablation_search` 指定 `max_experiments`（1–6）、`max_wall_minutes` 和 `max_gpu_minutes`；固定 `ablations` 与自动搜索互斥。普通复现、否定消融和已有 pytest 套件不会被自动改成消融。

模型先根据实际来源提出最多 8 个候选，再逐个评价信息增益、相关性、可复现性与风险。服务端使用确定性公式评分，按类别多样性、总预估时间、GPU 时间和实验数量筛选，保存全部候选、剔除 ID、预算和选择原因。树父节点必须存在，深度最多 2。评分和成本只是设计估计；实际任务仍受节点及计划时限约束，报告不能把估计当作测量。

候选生成失败时仅从已有设计或源码中真实存在的参数回退，不凭空添加命令；评分失败时明确标记确定性先验。选中配置进入后续代码准备，验收规则在实际运行前冻结，基线通过后才运行选中变体。原始输出、实际指标与选择记录一起写入报告；选中配置无法满足显式验收变体时阻止执行。

## 仓库、依赖与补丁

默认仓库压缩下载上限为 16 MiB，全部解包文件为 32 MiB，单文件为 16 MiB，最多 2,000 个文件。各项独立生效，路径、链接、重复文件、完整 SHA 和所属校验继续保留；不通过丢弃 Notebook/HTML 绕过预算。`OPENRESEARCH_SOURCE_MAX_*` 可显式收紧预算，超限仍失败。源码与测试候选的 AST 输入另限每文件 128 KiB，API 摘要仍最多 24,000 字节、64 个文件，每文件最多 64 项签名/返回项。固定参考实现的完整下载和实际核心检查见 [Annotated Transformer 验收](../examples/annotated-transformer-core/README.md)。

分支仅在准备时解析一次，保存完整 commit 和文件 SHA。依赖要求完整准确版本闭包，限制 CPython 3.12 / Linux x86_64 wheel，不支持 extras、URL、源码构建和任意安装脚本。运行前离线安装并校验实际发行包版本。

自动设计最多提出 32 个直接依赖请求，解析后的完整锁定闭包最多 128 个包；依赖下载总字节、工作区和任务时限仍受配置约束。框架来源元数据仅从实际 PyPI 查询取得，校验请求名称与固定版本并记录原始响应 SHA-256，不把模型建议的包名直接当作已安装或已验证的来源。

新计划可在科研执行阶段恢复真实安装失败或缺失公开模块。`environment.repair` 权限允许模型提出总计最多 8 项包添加、版本调整或删除，服务器保持用户显式版本约束、指定库、未授权删除的直接请求及绑定来源的框架版本，重新解析、校验完整 wheel 锁后在新容器安装；常见缺失模块有明确包映射。替换需要明确声明旧包删除和实际新包，不能移除受保护的库或用同名公开包替代仓库模块/标准库。环境与源码修复共用原节点最多 2 次修复预算，不能变更数据、验收规则、运行时和资源上限；「不要安装依赖」「不要修改代码」「不要自动修复」会收紧相应权限。

安装失败单列为 `RunAttempt.phase=install`，记录实际安装退出码、容器和锁摘要，未成功建立的 `environment` 为 null；不能当作科研程序已运行。`environment_changes` 保存提议、接受/拒绝原因、前后锁摘要和每次实际采用的完整锁，`final_environment_lock` 保存最终锁。预检恢复的环境随已核对回执传给正式运行；全量运行中的环境变更必须在新容器重新通过最多 8 条样本后才可继续全量任务。科研/框架首次准备与删除/替换恢复已接通，见 [环境恢复](environment-recovery.md)。自动运行时选择仍待迁移。

默认分支 `HEAD` 遇到 GitHub 元数据 API 配额耗尽时，通过 [Git smart HTTP 的引用发现协议](https://git-scm.com/docs/http-protocol#_smart_clients)读取真实 HEAD，再下载固定 SHA 的归档。不会猜测 main/master，也不会替换显式分支或标签；完整 SHA 直接下载归档。

补丁仅限 allowed_patch_paths，最多 3 个文件、总量 128 KiB。每个文件须匹配当前基础 SHA；先验证所有路径与 Python 语法再提交。最多 2 次修复，每次启动新容器；所有尝试保存累计可回放补丁与真实输出。失败也保留报告及证据，不转换为成功。

## 主张验收

rubric 在运行前规范化、编号、保存 SHA。来源引用必须逐字出现在声明上传文件的对应页。数值准则指定 metric_name、expected_value、operator、tolerance 和 variant。准则可为语义描述，但需要受约束的模型调用与已有执行证据。

状态包括 verified、partially_reproduced、contradicted、unverifiable、blocked_by_missing_asset。空准则、没有配置模型或缺少资产不会产生论文已复现结论。所有判定仅适用于声明的数据、参数与运行环境。
